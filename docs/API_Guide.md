# API Guide

Full interactive documentation is auto-generated by FastAPI at `/docs` (Swagger UI)
and `/redoc` once the backend is running. This guide summarizes the main resources.

Base URL: `http://localhost:8000`

All responses from `/` and `/health` use the standard envelope:
```json
{ "success": true, "message": "OK", "data": { ... }, "timestamp": "..." }
```
Resource endpoints (products, orders, etc.) return the resource(s) directly, per
FastAPI/Pydantic response models shown in `/docs`.

## Authentication
| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/auth/register` | Register a new user (`username`, `email`, `password`, `role`) |
| POST | `/api/v1/auth/login` | Authenticate, returns a JWT `access_token` |
| GET | `/api/v1/auth/me` | Current authenticated user (requires `Authorization: Bearer <token>`) |

## Categories
| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/categories` | Create a category |
| GET | `/api/v1/categories` | List categories |
| GET | `/api/v1/categories/{id}` | Get a category |

## Products
| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/products` | Create a product |
| GET | `/api/v1/products` | Search products (`keyword`, `category_id`, `brand`, `active_only`) |
| GET | `/api/v1/products/sku/{sku}` | Get by SKU |
| GET | `/api/v1/products/{id}` | Get by ID |
| PATCH | `/api/v1/products/{id}` | Partial update |
| DELETE | `/api/v1/products/{id}` | Delete |

## Inventory
| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/inventory` | Create a stock record for a product+location |
| GET | `/api/v1/inventory/low-stock` | List records at/below reorder level |
| GET | `/api/v1/inventory/product/{product_id}` | List records for a product |
| POST | `/api/v1/inventory/{id}/adjust` | Adjust stock by a signed delta with a reason |

## Customers
| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/customers` | Create a customer |
| GET | `/api/v1/customers` | List customers |
| GET | `/api/v1/customers/{id}` | Get a customer |

## Orders
| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/orders` | Place an order (reserves inventory, computes totals) |
| GET | `/api/v1/orders/customer/{customer_id}` | List a customer's orders |
| GET | `/api/v1/orders/{id}` | Get an order |
| PATCH | `/api/v1/orders/{id}/status` | Transition order status |

## RAG Knowledge Assistant
| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/rag/ingest` | Upload & ingest a PDF (multipart `file`) |
| POST | `/api/v1/rag/query` | Ask a question (`question`, optional `top_k`) |
| GET | `/api/v1/rag/documents` | List ingested documents & their status |

## AI Agents Studio
| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/agents/run` | Run agent(s) against a `project_brief` |
| GET | `/api/v1/agents/roster` | List available agents and their roles/goals |

## Feedback
| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/feedback` | Submit a rating/comments for an artifact type |
| GET | `/api/v1/feedback` | List feedback records |
| GET | `/api/v1/feedback/average-rating` | Average rating, optionally filtered |

## Example: Place an Order

```bash
curl -X POST http://localhost:8000/api/v1/orders \
  -H "Content-Type: application/json" \
  -d '{
    "customer_id": 1,
    "channel": "online",
    "items": [{"product_id": 1, "quantity": 2}]
  }'
```

## Example: Ask the RAG Assistant

```bash
curl -X POST http://localhost:8000/api/v1/rag/query \
  -H "Content-Type: application/json" \
  -d '{"question": "What is the discount on running shoes?", "top_k": 3}'
```
